\chapter{Naming convention for parity: Implementation detail}\label{anx:naming}

One of the challenging constraints of the Notion migration was \emph{byte-for-byte} column-name parity: downstream dbt models already reference the column names produced by the legacy Airflow loader, so the new dlt job had to emit exactly the same identifiers or every dependent model would break.

The difficulty is that dlt's default \texttt{snake\_case} convention actively rewrites identifiers in two ways that both cause drift. It strips a trailing underscore and appends one \texttt{x} per stripped character, turning \texttt{act\_owner\_\_display\_} into \texttt{act\_owner\_\_displayx}; and it collapses runs of \texttt{\_\_} into a single \texttt{\_}, turning \texttt{\_experimental\_\_\_\_blocked\_users} into \texttt{\_experimental\_\_blocked\_users}. Notion property names routinely contain such underscore runs, so both behaviours would silently rename columns.

The fix is a custom \emph{passthrough} convention that only lowercases and leaves underscores untouched. Two details make it work: the path separator is set to an out-of-band character (U+25B6) so dlt's path splitting never collapses the real \texttt{\_\_} sequences; and the convention declares itself case-insensitive, which makes the Snowflake destination emit \emph{unquoted} DDL. Snowflake then uppercases on storage, matching the production layout exactly.

\begin{lstlisting}[language=Python,caption={The passthrough naming convention (\texttt{jobs/notion/naming.py}).}]
from typing import ClassVar
from dlt.common.normalizers.naming.naming import NamingConvention as BaseNamingConvention


class NamingConvention(BaseNamingConvention):
    # dlt's default path separator is "__"; normalize_path splits at every
    # "__", drops empty segments, then rejoins -- collapsing multi-underscore
    # identifiers. Notion property names regularly contain runs of underscores,
    # so we use an out-of-band separator to dodge the collision.
    PATH_SEPARATOR: ClassVar[str] = "\u25b6"  # U+25B6, out-of-band separator

    def normalize_identifier(self, identifier: str) -> str:
        identifier = super().normalize_identifier(identifier)
        # lowercase only -- underscores are preserved verbatim
        return self.shorten_identifier(identifier.lower(), identifier, self.max_length)

    @property
    def is_case_sensitive(self) -> bool:
        return False  # -> unquoted DDL, Snowflake uppercases on storage
\end{lstlisting}

\chapter{CESOP: the Digipoort FTPS/mTLS client}\label{anx:ftps}

The transport client is the part of the CESOP project that departs most from ordinary data engineering (Chapter~\ref{ch:cesop}). Digipoort speaks \emph{explicit} FTPS (FTP secured with TLS). Before any file can move, the client must open the control channel, negotiate TLS, secure the data channel, and log in. The exact command dialogue is fixed by the Logius interface specification~\cite{digipoort-ftps}; Listing~\ref{lst:ftps-raw} reproduces it (\texttt{S:}~= server response, \texttt{C:}~= client command).

\begin{lstlisting}[caption={Setting up a TLS connection from Digipoort FTP interface specification~\cite{digipoort-ftps}.},label={lst:ftps-raw}]
<client opens a connection on tcp/21>
S: 220 oe.procesinfrastructuur.nl ready
C: AUTH TLS
S&C: <TLS connection is negotiated and set up>
S: 234 Security data exchange complete
C: PBSZ 0
S: 200 Protection Buffer Size set to streaming
C: PROT P
S: 200 Data connection is private
C: USER bank
S: 331 Username OK, need password for login
C: PASS "the bank's password"
S: 230 User logged in, proceed.
\end{lstlisting}

Each step maps onto a single call in the client: \texttt{AUTH TLS} becomes \texttt{ftp.auth()}, \texttt{PBSZ~0}\,/\,\texttt{PROT~P} becomes \texttt{ftp.prot\_p()}, and \texttt{USER}\,/\,\texttt{PASS} becomes \texttt{ftp.login(...)}. What the specification does \emph{not} spell out are the two implementation difficulties that cost the most effort.

\emph{TLS session reuse.} Digipoort, like many government FTPS servers, requires the data connection to \emph{resume} the control connection's TLS session. Python's standard \texttt{ftplib} instead opens a fresh, independent handshake for each data transfer, which the server rejects. The fix is to subclass \texttt{FTP\_TLS} and override \texttt{ntransfercmd} so the data socket is re-wrapped with the control socket's TLS session.

\emph{Dual authentication from in-memory secrets.} Authentication is twofold: a PKIoverheid client certificate (\textbf{mTLS}) \emph{and} an FTP username/password. The certificate and key arrive as PEM \emph{text} from the secret store, but \texttt{ssl.load\_cert\_chain} only accepts file \emph{paths}; they are therefore written to short-lived \texttt{0600} temporary files, loaded into the SSL context, then deleted immediately, so nothing sensitive lingers on disk. In production the Logius server CA is added explicitly to the trust store (Listing~\ref{lst:ftps}).

\begin{lstlisting}[language=Python,caption={The Digipoort FTPS/mTLS connection client},label={lst:ftps}]
import ftplib, os, ssl, tempfile


class _SessionReuseFTPTLS(ftplib.FTP_TLS):
    """FTP_TLS that reuses the control channel's TLS session on the data channel.

    Digipoort requires the data connection to resume the control channel's TLS
    session; stdlib ftplib opens a fresh handshake and is rejected.
    """

    def ntransfercmd(self, cmd, rest=None):
        conn, size = ftplib.FTP.ntransfercmd(self, cmd, rest)
        if self._prot_p:
            conn = self.context.wrap_socket(
                conn, server_hostname=self.host, session=self.sock.session
            )
        return conn, size

def _build_ssl_context(cert_pem, key_pem, passphrase, *, server_ca_pem):
    """Build an mTLS SSLContext from in-memory PEM text.

    ssl.load_cert_chain only accepts file *paths*, so cert/key are written to
    short-lived 0600 temp files, loaded, then deleted immediately.
    """
    ctx = ssl.create_default_context()
    if server_ca_pem:                       # production: trust the Logius CA
        ctx.load_verify_locations(cadata=server_ca_pem)

    cert_fd, cert_path = tempfile.mkstemp(suffix=".pem")
    key_fd, key_path = tempfile.mkstemp(suffix=".key")
    try:
        with os.fdopen(cert_fd, "w") as fh:
            fh.write(cert_pem)
        with os.fdopen(key_fd, "w") as fh:
            fh.write(key_pem)
        ctx.load_cert_chain(cert_path, key_path, password=passphrase or None)
    finally:
        os.unlink(cert_path)                # key stays parsed in the context;
        os.unlink(key_path)                 # the PEM files are gone
    return ctx

class DigipoortClient:
    # __init__ just stores host/port/credentials/cert/key from config.
    def connect(self):
        """Open the control channel, do AUTH TLS + login, then enable PROT P."""
        ctx = _build_ssl_context(
            self._cert_pem, self._key_pem, self._passphrase,
            server_ca_pem=self._server_ca_pem,
        )
        ftp = _SessionReuseFTPTLS(context=ctx, timeout=self._timeout)
        ftp.connect(self._host, self._port)
        ftp.auth()      # AUTH TLS  -> encrypt control channel (client cert = mTLS)
        ftp.login(self._username, self._password)
        ftp.prot_p()    # PBSZ 0 + PROT P -> encrypt the data channel
        self._ftp = ftp
\end{lstlisting}

\chapter{Digipoort acknowledgements}\label{anx:receipts}

After a submission, Digipoort drops response files into an \texttt{out/} folder that DAG~B polls (Chapter~\ref{ch:cesop}). Four artefact types can come back, and the acknowledgement parser normalises all of them into a single \texttt{ParsedReceipt} so the poll flow does not branch on each format:

\begin{enumerate}
  \item a transport confirmation (\texttt{.ok}): an \texttt{otp-metadata} (metabestand) carrying a \texttt{<transport><received>} timestamp; correlation is the payload filename in \texttt{data-reference/@id};
  \item a transport rejection (\texttt{.error}): \emph{plain text, not XML}: a \texttt{Foutcode} (error code in Dutch): line followed by a (possibly multi-line) \texttt{Foutomschrijving:} description, e.g.\ \texttt{Foutcode: ALS400};
  \item a Belastingdienst technical response: an xml file with root \texttt{Responsemessage}, sent on error only;
  \item a CESOP business-validation response: an xml file with root \texttt{CESOP} and a \texttt{ValidationResult} of \texttt{VALIDATED}, \texttt{PARTIALLY REJECTED} or \texttt{FULLY REJECTED}.
\end{enumerate}

Listing~\ref{lst:ack-ok} shows the transport confirmation; Listing~\ref{lst:ack-cesop} shows the two extremes of the business validation. The rejection is what drives the Slack alert in Figure~\ref{fig:cesop-slack}.
